## Один бот: @YassirAppBot — голос в личке, потом и в группах

**Повод.** Вход новичка — три двери: YassirApp → бот половины («Старт») → подготовительная. Новичок путается.

**Анализ (без кода).**
- Боты половин пишут студенту в личку ~40 местами: вход, онбординг (4 экрана), джуз (кнопки), выпуск + ссылка на группу, переводы/кики/предупреждения, upgrade relaxed→pro (кнопки), напоминания, «вернись», разбор сдач, анкета (свободный текст, на паузе).
- Почти везде развилка «личка открыта / иначе группа или ничего»; при выпуске без dm_ok ссылку на новую группу человек не получает вовсе (`prep.py:412`).
- Вход в подготовительную прямо из YassirApp технически уже возможен: заявку решает бот половины по общей `user_side`.

**Решения пользователя.**
- Мягкий переход: у человека один канал. Нажал Старт у YassirApp → всё через него; нет → по-старому через бота половины; старым один раз «нажми Старт у YassirApp».
- Направление: постепенно всё на @YassirAppBot; позже его добавить и в группы и отказаться от двух ботов половин.

**Согласованная архитектура (предложение Claude, принято направлением).**
- Данные половин остаются раздельными (две базы, два процесса). Единым становится только голос/дверь.
- YassirApp-слушатель = маршрутизатор: апдейт → половина (группа — по chat_id, личка — по базам/`user_side`) → процесс половины обрабатывает как сейчас и отвечает токеном YassirApp. Мужской процесс в женскую базу не пишет.
- Строить сразу так, чтобы этап «группы» был включением по группе (флагом, волнами как app_only), а не переписыванием.

**Решено:** устазы/суперадмины на этапе 1 остаются на ботах половин; «Старт у YassirApp» — часть регистрации вместо «Старта у бота половины» (меняет решение 22.09).

**План этапа 1 (личка), каждый шаг отдельной выкладкой:**
1. Основа: отметка «Старт у YassirApp» в hadiths.db (снимается при блокировке); токен YassirApp в женский .env (только отправка); одна функция «написать студенту» (YassirApp → бот половины → «не дошло»).
2. Входящие: очередь в hadiths.db (как tadabbur_mirror, в обратную сторону) — кнопки/ответы/«первый Старт» уходят половине, обработчики те же, callback_data не меняются.
3. ~40 мест личных сообщений студентам → на одну функцию; призывы «нажмите Старт» → на YassirApp; служебное устазам не трогаем.
4. Вход в две двери: YassirApp → половина → сразу ссылка на prep (ссылку каждая половина публикует в общий реестр).
5. Приложение из YassirApp: menu button, сервер принимает подпись токена YassirApp, фронт выбирает половину как при входе с сайта.
6. Мягкий переход старых: разовое «нажми Старт у @YassirAppBot»; нажал — дальше только YassirApp.
**Принцип выкладки (требование пользователя: «никто не должен заметить, ничего не ломается»):** у каждого шага флаг (по умолчанию выкл.); включение кругами — тестовый аккаунт/суперадмины → только новички → волны старых; при любой неудаче YassirApp — сразу старый путь через бота половины; старую личку ботов половин не удаляем; тексты те же, меняется только отправитель; лог канала и откатов, проверка после каждого круга.
**Поправка:** шаг 6 (просьба старым «нажми Старт») отложен до этапа 2 — старые на этапе 1 ничего не замечают, через YassirApp идут только новички.

**Правило переключения (уточнение пользователя):** нажал Старт у YassirApp → вся личка только через YassirApp, бот половины в личке этого студента замолкает (на его сообщения — одна строка «я теперь в @YassirAppBot»). Группы бот половины ведёт до этапа 2. Исключение: YassirApp заблокирован → аварийно снова пишет бот половины.

Риск: слушатель в мужском процессе — вынести отдельно к этапу 2 (группы).
