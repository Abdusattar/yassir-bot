# 17.08.2026 — сессия

## Дедуп насыхи Тадаббур (коммиты `58fe3e5`)

Пользователь заметил: мужской и женский боты независимо генерируют насыху
для Тадаббур двумя вызовами ЛЛМ в день — не только приветствие разное,
а весь текст (гендерное обращение зашито в system-промпт), плюс аят/хадис
выбираются независимо из общего `sources/hadiths.db` (гонка за `used_at`).

**Решение:** 08:55 — только мужской бот генерирует (`neutral=True`, без
гендерного обращения и приветствия) и кладёт в общий кэш
(`daily_nasiha_cache` в `sources/hadiths.db`, файл общий для обоих ботов).
09:00 — оба бота читают кэш, подставляют своё приветствие («Ассаляму
алейкум, братья!»/«...сёстры!»). Fallback на самостоятельную генерацию,
если кэша нет (мужской бот не работал). Побочный эффект: оба чата теперь
получают один и тот же аят/хадис в день.

Проверено через advisor дважды, на проде подтверждено что у ботов разные
`chat_id` Тадаббур-группы (не один чат на двоих), живая генерация
проверена на сервере до отправки. Задеплоено на оба бота.

## Редизайн анкеты "откуда и сколько лет" (коммиты `0846564`, `f40ce35`, `12f54b8`)

Первый вопрос: рейтинг baллов (не по теме анкеты) — попутно вспомнили
задачу с анкетой из 13.08, которая ждала решения Умар устаза.

**Полный редизайн, по ходу многораундового обсуждения с пользователем:**

1. **Триггер сменён** с "30 дней после регистрации" на "2 дня после
   перевода в постоянную группу" (`user_groups.joined_date`) — у старых
   студентов между регистрацией и реальным началом мог быть большой
   разрыв.
2. **Без батчинга по 5/день** — разовый запуск всем подходящим сразу,
   прямое решение пользователя (снята осторожность от 13.08).
3. **Текст вопроса про локацию переформулирован** — не "откуда родом", а
   "откуда сейчас сдаёшь задания" (для КР — район/город, не село; для
   остальных — просто страна).
4. **Возраст → год рождения** (`survey_birth_year`), не сам возраст,
   чтобы не устаревал. Сырой ответ тоже хранится.
5. **Окно ответа — 24 часа** (`survey_answer_in_window`) — ответ,
   пришедший позже, не перехватывается как ответ на анкету (иначе
   случайное сообщение через дни могло ошибочно записаться). Не
   ответившим за неделю — тот же вопрос повторяется
   (`profile_survey_nudge`), без сброса прогресса.
6. **Переспрос на непонятный ответ (один раз, не бесконечно):**
   возраст — если нет числа (`asked_age_retry`); локация — если голое
   приветствие вместо места (`location_retry`, найдено на живых
   ответах — 3 из первых 10 ответили "Ваалейкум ассалам" вместо
   города). Приветствие убрано из текста первого вопроса как основная
   профилактика.
7. **Исключение админов снято** (была защита от 13.08 — устаз-студент мог
   попасть в анкету, и его обычная команда перехватилась бы как ответ,
   застряв навсегда). Теперь безопасно благодаря окну 24ч. Решение
   пользователя — он сам одновременно супер-админ и студент ("я
   студент, поэтому да включать"). Чистых админов без активной роли
   student нигде (Умар устаз) это не касалось и не касается.

**Живой запуск:** включено на мужском боте, выключено на женском (прямая
просьба пользователя — "пока опрос мужскому боту только"). Отправлено
вручную (не дожидаясь 07:00) — сначала 74 обычным студентам, потом
отдельно 11 устазам-студентам после снятия фильтра (итого 85). К концу
сессии — 21 из 85 полностью ответили.

Каждый шаг редизайна прогонялся через advisor до коммита — поймано и
исправлено: гонка окна для nudge (backfill `survey_stage_at`), отсутствие
group_type-фильтра в nudge-запросе, ложное срабатывание переспроса на
короткие легитимные ответы типа "Ош" (порог `<=2` вместо `==0`).

`wiki/engagement_broadcasts.md` обновлён под новую версию (описывал
версию от 13.08 — сбивал бы с толку в следующей сессии).

## Новая воронка регистрации через Start — дизайн, без кода

В конце сессии пользователь предложил развернуть точку входа новых
студентов: сейчас регистрация целиком в группе (первое сообщение →
`extract_name`), Start в личке — отдельный, более поздний шаг со всей
инфраструктурой `dm_ok`-нагонов. Идея: сначала Start-ссылка → личка
спрашивает имя → потом ссылка на подготовительную.

**Согласованный минимум (фаза 1):** только имя (без фамилии — "потом
посмотрим, если тёзки станут проблемой"). Откуда/возраст остаются на
своём месте (2-й день после перевода в постоянную группу — см. выше,
не переезжают). Старая прямая ссылка на группу остаётся жить
параллельно — не для всех, миграция постепенная через существующие
каналы (в первую очередь `invite_friend_broadcast`, переключить на
новую ссылку).

Проверено в коде: `/start` сейчас не парсит deep-link payload; для
совершенно нового человека в личке DM-регистрации не существует вообще
(отвечает "напиши в группе"). Это новый узел логики, не мелкая правка.
НЕ проверено: подхватывает ли существующий флоу вступления в группу
уже известного по телефону/имени человека без повторного вопроса об
имени — нужно проверить до реализации.

**Решение:** записать в бэклог (`project_dm_first_registration_funnel.md`),
не начинать реализацию в этой же сессии — уже 4 продакшн-деплоя и живая
рассылка 85 студентам сегодня.
