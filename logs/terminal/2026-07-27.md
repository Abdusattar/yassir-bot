## Фикс: детерминированная сверка с текстом Корана

- Новый модуль `core/quran_ref.py` + статический индекс
  `core/quran_word_index.json` (644KB, 14868 нормализованных форм,
  построен оффлайн через `quran_transcript`, сервер не требует эту
  зависимость в рантайме).
- `strip_quran_confirmed_words()` - убирает строки муфрадат-вердикта,
  где ИИ придирается к слову, которое студент написал ТОЧНО как в Коране
  (с учётом опечаток на 1-2 буквы через Левенштейна на нормализованной форме).
  Подключено в `_verify_and_reply` (`core/handlers.py`), только для
  mufradat (не hadith - нет корпуса для сверки).
- Валидация: `tajweed_ai/scripts/verify_quran_index_filter.py` на всех 20
  flagged-записях - подтверждено: оба ложных срабатывания (id=128, id=137)
  корректно вычищаются до ВЕРНО, ни одна из ~17 настоящих ошибок не задета.
  Побочный бонус: заодно убирает "перечисление верных слов" (нарушение
  правила из промпта) в нескольких записях (id=121, 140, 152, 159, 162).
- НЕ чинит false negatives (пропущенные реальные ошибки) - отдельная,
  более рискованная задача (риск ложных срабатываний на нецитатной лексике),
  решили не брать сегодня.
- Approach выбран по совету advisor: пост-фильтр (по образцу уже
  существующих `_strip_phantom_errors`/`_strip_tajweed_silence_violations`/
  `_strip_nahw_exact_phantoms`), НЕ prompt-injection эталонного текста и НЕ
  трекинг текущего аята студента (заблокирован - в БД нет поля с текущим
  аятом, гадать хуже, чем не проверять).

## Клавиатурное исключение для хамзы-на-алифе

- Пользователь (это была его собственная запись, id=150 "Сатар"): на
  телефоне нет клавиши "алиф с хамзой", набирать сложно/не всегда есть.
- Проверено поиском (не поверил на слово): подтверждено -
  arabictyping101.com/en/guide/arabic-101-keyboard - именно أ/إ (и آ)
  требуют Shift/долгое нажатие на стандартной раскладке Arabic 101, в
  отличие от ة (та-марбута), ى (алиф-максура), ؤ/ئ/ء (остальные формы
  хамзы) - те все на основном слое, набираются так же легко, как обычная
  буква.
- Из 4 изначально найденных пропущенных ошибок 3 оказались именно этой
  заменой (اخيه/أخيه, فاخذтكم/فأخذتكم, اقررтм/أقررтم) - решили не флагать
  этот конкретный случай (клавиатурное ограничение, не пробел в знаниях),
  остальное (ة/ه, ى/ي, обычные буквы) - флагать как и раньше.
- Добавлено `_is_alif_hamza_only_diff()` в `core/quran_ref.py` -
  исключает находки, где единственная разница - одна форма алифа (ا/أ/إ/آ)
  вместо другой. Тесты обновлены и зелёные - реальная ошибка (Бекхан
  هلفهم, разные буквы) по-прежнему ловится, три алиф-хамза случая теперь
  корректно не флагаются, precision (0 на 16 flagged=0) не пострадала.

## Горячий фикс: uthmani-написание в муфрадате (репорт группы 7)

- Прямо во время работы над таджвидом пользователь принёс живой кейс:
  группа 7, аят 2:45 - студент прислал муфрадат в кораническом
  (uthmani) написании (ٱسْتَعِينُوا۟, ٱلصَّلَوٰةِ, скопировано из
  мусхаф-приложения) - только что задеплоенный `find_unconfirmed_words`
  дал 2 ложных "не найдено в тексте Корана".
- Причина: индекс строился только по imlaey (стандартному) написанию.
  Две разные проблемы внутри uthmani-текста:
  1. коранические значки рецитации (напр. ۟ - "молчащая" концевая буква),
     которых нет в imlaey;
  2. настоящая рسм-альтернация письма - часть слов пишется через و/ي с
     надстрочным алифом вместо полного ا (ٱلصَّلَوٰةِ вместо الصلاة) -
     не опечатка, а другой способ записи того же слова.
- Первая попытка - расширить regex снятия огласовок под уthmани-значки -
  ОТКАЧЕНА: часть тех же значков (small waw/yeh) в других словах реально
  заменяет букву (إِيلَافِهِمْ пишется إِۦلَـٰفِهِمْ), угадывание по
  символам сломало recall-тест на реальной ошибке Бекхана (هلفهم).
- Верное решение (без угадывания) - индексировать ОБЕ формы слова
  (imlaey и uthmani) как есть через `quran_transcript`. Индекс вырос с
  14868 до 22391 ключей (644KB -> 1MB). Build-скрипт перенесён из
  scratchpad в репозиторий - `tajweed_ai/scripts/build_quran_word_index.py`
  (был потерян в прошлый раз, пришлось искать 40 минут).
- Regression-тест `tajweed_ai/scripts/verify_uthmani_script.py` (дословный
  кусок репорта пользователя, не пересобранный через quran_transcript) +
  оба существующих теста - все зелёные, полный набор pytest (25) тоже.
- Закоммичено (`3d05260`) и запущено - задеплоилось на мужского бота
  автоматически при пуше.
- Побочная находка (не баг, известное ограничение): слова, которые
  куррикулум учит отдельно от предлога-приставки (بِ + ٱلصَّبْرِ), в
  самом тексте Корана НИКОГДА не стоят раздельно (بِٱلصَّبْرِ - одно
  слитное слово) - страхует только "неоднозначность = не флагаем"
  правило find_unconfirmed_words, отдельно не чинили, вне сегодняшнего
  скоупа.
