# ИИ-проверка таджвида — рабочая папка R&D

Долгосрочная цель: снизить нагрузку на устаза при проверке голосовых сдач,
постепенно передавая ИИ куски задачи по мере подтверждённой точности —
не разовая замена устаза. Полный лог решений, тестов и выводов — в
`wiki/ai_tajweed_audio.md` (корень проекта). Эта папка — рабочее место
самого R&D: аудио, скрипты, промежуточные данные.

## Статус (на 14.09.2026)

Корпус накопился сам: 201 голосовая коррекция Умар устаза + 179 сдач
хифза из YassirApp с вердиктом и пометками слов. Gemini как «писарь»
голоса устаза подтверждён на слух. Muaalem на реальных сдачах: после слоя
правил v2 (`scripts/rules_offline.py`) «лишняя растяжка» — 0,8% ложных на
принятых строчках, 5/6 пометок на странице 5074; «короче»/гунна — шумят.
План: модель предлагает → Умар устаз ✓/✗ → дообучение. Подробности и
следующий шаг — `wiki/ai_tajweed_audio.md`, раздел 14.09, и
`context/summary.md`.

Скрипты дня: `fetch_umar_corpus.py --only verdict|voice`, `hifz_eval.py`
(Шаг 1, кусками ≤45 с, сохраняет группы модели), `rules_offline.py`
(правила v2 по сохранённым группам), `ustaz_voice_classify.py` (Шаг 2,
Gemini через OR — запускает пользователь через `!`). Ключ OR — в `.env`
этой папки. Два экземпляра Muaalem параллельно на этом компьютере не
влезают в память.

## Структура

- `audio/` — сырые записи
  - `*.mp3/.m4a/.ogg` в корне — реальные сдачи студентов (Бакыт, Сатар,
    Нурсултан) + голосовые коррекции устаза Умар к каждой
  - `control/` — эталонные чтения (заведомо верные): Хусари и Афаси,
    Аль-Бакара 106–112, по аятам и одним файлом
- `scripts/` — код анализа (Python, torch/transformers/librosa)
- `data/` — промежуточные и итоговые данные (decode-выводы модели,
  канонический текст, результаты гейтов)
