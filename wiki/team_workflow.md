# Как работает команда Яссир (предложение, 05.11.2026)

Для всей команды Яссир — тех, кто пишет код, Умар устаза и всех, кто
участвует в совете, — и для всех Claude/Fable, которые работают с
репозиторием. Это **предложение**: после обсуждения в группе фиксируем, что
приняли, и переносим в `CLAUDE.md`. Просьба прогнать через свой Claude/Fable:
что лишнее, что упущено, что неудобно в вашем рабочем процессе.

Связанный разбор: `wiki/architecture_roadmap.md` (архитектура и уход от
Telegram).

## Как устроена работа

**Советуемся вместе → решаем вместе → каждый делает свою часть.** Над
кодом работают несколько человек, у каждого свой Claude/Fable; завтра
могут прийти новые.

- **Решения** — общие: что делаем, зачем, в каком порядке, на каком стеке.
  Обсуждаем в группе, договариваемся, записываем в wiki. Методику и всё,
  что касается Корана, сверяем с Умар устазом.
- **Части работы** — у каждого свои и меняются по договорённости. Кто что
  ведёт сейчас — пишем коротко в группе, а не в этом документе.
- **Опыт** — у каждого свой, и в своей области его голос весит больше:
  веб и интерфейс, методика и студенты, Коран и таджвид.
- **Claude/Fable** — помощники каждого: пишут код, тесты, wiki, следят за
  тем, чтобы правила команды соблюдались.

Обязательное ревью человеком не вводим: оно застопорит работу. Замена —
зелёные тесты + ИИ-ревью PR (Claude или Fable) + снимок экрана для UI.

## Что сегодня мешает

Это про привычки и устройство репозитория, а не про людей:

- десятки коммитов идут прямо в `master`, без PR;
- PR сливаются через 1–2 минуты, без ревью и до прогона тестов;
- файл однажды загружен целиком через сайт GitHub — при несвежей копии так
  молча откатываются чужие правки;
- слитые ветки не удаляются, PR #1 открыт с июля;
- в рабочей копии одной из сессий лежат чужие незакоммиченные правки;
- правило перехода 40+40 живёт уже в трёх копиях (третью добавил Claude
  05.11);
- `mushaf_data/index.html` (18 тыс. строк) — 60 из 187 коммитов за месяц.
  Пока это один файл, все неизбежно в нём встречаются.

## Правила (предложение)

1. **Перед работой — `git pull`. Правки — через git** (GitHub Desktop или
   VS Code), а не загрузкой файла через сайт. Тогда git сам покажет
   конфликт, а не затрёт чужое.
2. **Перед большой правкой `index.html` — одно сообщение в WhatsApp:**
   «сегодня трогаю X». Мелочь — без предупреждения.
3. **Всё через PR, у всех** — по мере возможности. PR =
   короткое «что и зачем» + снимок, если менялся экран.
4. **Перед слиянием PR:** зелёные тесты (нужно включить проверку на PR,
   см. ниже) + ИИ-ревью. Сливать можно самому.
5. **Кто выкатил — тот проверяет прод.** Слияние в `master` = выкатка на
   yassirilm.com. После неё: Actions зелёный и сайт реально обновился.
6. **Ветку после слияния удаляем** (в настройках GitHub — галочка
   «Automatically delete head branches»).
7. **UI — снимок 390×844 глазами до слияния**; арабское и RTL — только по
   скриншоту; iPhone от iOS 16.2.

## Общая память для ИИ — важное

Память Claude **локальная**: у одного участника накопилось ~130 правил
проекта, и они лежат только на его компьютере — другие Claude/Fable их не
видят. А там много правил, которые важны
всем. Значит, общие правила должны жить **в репозитории**: в `CLAUDE.md`
(его читает любой Claude/Fable, открывший проект) и в `wiki/`.

Ниже — готовый блок для `CLAUDE.md`. Вставим после согласия команды.

> **Никогда не переносим в репозиторий** токены, ключи, адрес сервера,
> SSH: репозиторий публичный.

### Общие файлы — чтобы не конфликтовать

`CLAUDE.md` просит каждого Claude вести `logs/terminal/ДАТА.md` и
`context/summary.md`. Если сессии разных людей пишут в один файл в
один день — конфликт. Предложение: лог с автором в имени
(`logs/terminal/2026-11-05_erlan.md`), а в `context/summary.md` — свои
разделы.

### Готовый блок для `CLAUDE.md` (после «да» команды)

```markdown
## Команда и порядок работы

- Команда Яссир советуется и решает вместе, потом каждый ведёт свою часть
  со своим Claude/Fable. Методику и всё о Коране — сверять с Умар устазом.
  Объяснять решения без жаргона: «что даёт / чем рискуем».
- Перед работой `git pull`; правки только через git, не загрузкой через сайт.
- Большая правка `mushaf_data/index.html` — сначала сообщение в группу.
- PR: «что и зачем» + снимок 390×844 для UI; зелёные тесты + ИИ-ревью; ветку удалить.
- Кто выкатил — проверяет прод (Actions + yassirilm.com).
- Свой лог: `logs/terminal/ДАТА_имя.md`.
- Сначала русский; ky/uz/zh потом одним проходом (`T()` откатывается на ru).
- Правило 40+40 (строки, половины, переход, склейка стр. 1–2) — сейчас в трёх
  копиях: `index.html`, `core/mushaf_words.py`, `scripts/generate_hifz_audio.py`.
  Меняешь одну — меняй все, пока не сведены в одну.
```

## Что сделать технически (предложение, без «да» не делаем)

- Workflow тестов на `pull_request` — PR видит зелёный/красный до слияния.
- Галочка автоудаления веток в настройках репозитория.
- Закрыть или слить PR #1 (открыт с июля).

## Вопросы к тем, кто пишет код

1. Где вы обычно работаете с кодом: сайт GitHub, GitHub Desktop, VS Code?
2. Как запускаете Claude/Fable: в Claude Code внутри репозитория (тогда `CLAUDE.md`
   и wiki он прочитает сам) или в чате claude.ai (тогда документы
   придётся вставлять вручную)?
3. На чём сделаны ваши веб-проекты: React, Vue, другое? От этого зависит
   выбор стека (см. `wiki/architecture_roadmap.md`).
4. Что из правил выше неудобно или лишнее?
