### 1.2 Правила слоя

1. **У каждой вещи одно место.** Всё остальное — производное, собирается скриптом и руками
   не правится. Новая копия «на всякий случай» или «на язык/раскладку» — запрещена.
2. **Данные людей (А) и содержание (Б) не смешиваются** в одном хранилище без нужды: у них
   разная цена потери и разный порядок копирования.
3. **Данные людей копируются автоматически и вне сервера.** Ручная копия «перед загрузкой» —
   это страховка от ошибки скрипта, а не резервная копия.
4. **Содержание (Б) живёт в git**, если его создал человек или ИИ (переводы, вёрстка, тексты):
   у него должны быть история и откат. В базу оно попадает загрузчиком, не наоборот.
5. **Половины не смешиваются:** данные братьев и сестёр — в разных базах; общая база хранит
   только то, что по устройству общее, и каждая строка знает свою половину.
6. **Прод-базу руками не править** (CLAUDE.md): причина — в коде, чинится код.
7. Слово Корана адресуется `сура:аят:позиция` — один ключ для мусхафа (обе раскладки),
   тренажёра, переводов, пояснений.

### 1.4 К чему идём

Три хранилища с понятной ценой: **(1) люди** — базы половин + база приложения, с ночной

### 2.2 Правила слоя

1. **Результат сборки руками не правится** — правится источник и пересобирается.
2. **Шаг, который надо «не забыть», — это долг.** Сборка либо запускается сама (выкатка,
   загрузчик), либо её пропуск ловит тест. Третьего не должно быть.
3. **Сборка воспроизводима:** тот же вход — те же байты; у каждого результата записано,
   из чего и чем он получен (таблица выше).
4. **Проверка — часть конвейера, а не привычка.** Перевод: шесть ворот
   (`wbw_ru_method.md`); приложение: `test_app_build.py`, `test_sw_syntax.py`; подписи:
   `test_wbw_ru_files.py`.
5. **Правки готовых данных — только скриптом со сверкой «было»** (`wbw_ru_apply.py`), не
   руками и не из текста с пометками.
6. Скрипт многоразовый — в `scripts/` с описанием в шапке; разовый — назван разовым и
   после дела удалён.
7. **Что выполняется на сервере руками — записано списком** (сейчас: `load_wbw_ru.py`,
   `load_wbw_zh.py`, `patch_mushaf_ru.py`). Всё остальное туда приезжает выкаткой.

| Раздача файлов | nginx, корень `/var/www/yassir-app`: `index.html`, `sw.js` копируются выкаткой; листы, `dm/`, `meaning/`, `wbw/`, `audio/` — ссылки на `mushaf_data` |

| Доступ | ssh; учётки `stursunkul` (владелец) и `claude-access` |

### 3.2 Правила слоя

1. **Пуш в master = выкатка.** Руками на сервере не перезапускать и код не править.
2. **Сервер ничего не считает на запрос за файлом** — листы, переводы, звук раздаются готовыми;
   работа процесса бота — только API и Telegram.
3. **Секреты — только в `.env` / `.env.female`**, читает только владелец; в git и в скриптах
   их нет.
4. **Настройка сервера записана в git** (nginx, службы, расписание, скрипты наблюдения) —
   чтобы машину можно было поднять заново по записи, а не по памяти.
5. **О поломке узнаём от наблюдения, а не от студентов:** оба бота, диск, ночная копия,
   сертификат.
6. Половины разделены до сервера включительно: свой процесс, своя база, свой путь API.

| П6 | Любой пуш кода перезапускает оба бота, даже если изменилась только статика приложения | секунды простоя API на каждую правку | в выкатке: не перезапускать, если изменились только `mushaf_data/`, `app_src/`, `i18n/wbw_ru/` |

## Слой 4. Приложение

Опись 14.11.2026 (`app_src/`, `sw.js`). Подробности — `mushaf_yassirapp.md`, `index_split_plan.md`.

### 4.1 Как устроено

| Что | Как ✔ |
|---|---|
| Оболочка | одна страница `index.html` (1,3 МБ), собирается из `app_src/`: 46 кусков JS (14 700 строк, **одно общее замыкание**) и 19 CSS |
| Данные | 51 адрес API (`/api/muf/…`) — всё личное; листы, переводы, смысл, звук Хусари — готовыми файлами |
| Лист мусхафа | один загрузчик `fetchPageData` (с 14.11): лист раскладки + переводы слов из `wbw/` по отпечатку; предзагрузка 10 листов вперёд и 2 назад |
| Без сети | service worker, три кэша: оболочка (сеть вперёд), листы и переводы (кэш вперёд, обновление в фоне), шрифты (навсегда). В Telegram WebView его нет — там кэш nginx |
| Свежесть | оболочка: `/api/muf/version`; `wbw/`: отпечаток в адресе; листы `dm/` и `meaning/`: **ручные номера** (`DM_DATA_VER`, `MEANING_VER`); версия кэшей SW — ручная `v1` |
| Память телефона | 13 ключей localStorage (язык, раскладка, страница, …) — удобства, не данные |
| Внешние зависимости | SDK Telegram, звук с verses.quran.foundation, шрифты (зеркало у нас, запас — CDN tarteel), corpus.quran.com (ссылки), YouTube (уроки) |
| Языки | ru/ky/uz/zh; новые фичи сначала ru, `T()` откатывается на ru |
| Вход | Telegram или свой (почта, код) — `login_without_telegram.md` |

### 4.2 Правила слоя

1. **Правится `app_src/`, не `index.html`** — и пересобирается (`build_app.py`).
2. **Личное — через API, общее — готовым файлом.** Общие данные не запрашиваются у процесса бота.
3. **Один загрузчик на вид данных.** Лист, перевод, смысл грузятся каждый одной функцией;
   копировать `fetch` по экранам нельзя (до 14.11 лист грузился в пяти местах).
4. **Свежесть — отпечатком содержимого в адресе**, не ручным номером. Кэш при выходе не
   чистится (решение 14.11): он держит одну запись на файл и заменяет её при новом отпечатке.
5. **Экран открывается сразу и работает на слабой сети:** сначала то, что есть, недостающее
   дописывается; ни один запрос не держит экран дольше пары секунд.
6. **Телефон не хранит единственную копию ничего важного** — localStorage только для удобств.
7. Любая правка вида — снимок 390×844 до пуша; обе раскладки; iOS Safari от 16.2.
8. Зависимость от чужого сервера — только с запасным путём (как шрифты V4 после сбоя CDN).

### 4.3 Долги слоя (названы 14.11.2026)

| № | Долг | Чем грозит | Что делать |
|---|---|---|---|
| Р1 | Ручные номера версий для `dm/`, `meaning/`, кэшей SW (он же С5) | забыли поднять — старое на телефоне | **единый манифест отпечатков** для листов, смысла и переводов |
| Р2 | Лист ждёт переводы до 2,5 с, потом берёт вшитые (переходное решение 14.11) | после шага 3 вшитых не станет | «лист сразу, подписи дописываются по приходу» — до шага 3 |
| Р3 | Весь код — одно замыкание в одном файле 1,3 МБ, без типов и модулей | любая правка может задеть любой экран; тесты не открывают приложение в браузере | `index_split_plan.md`; стек по опыту Эрлана, TypeScript (`architecture_roadmap.md`) |
