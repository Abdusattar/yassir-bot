## Часть 1. Как устроен код сейчас

### Карта

- **Фронтенд — один файл `mushaf_data/index.html`, 18 037 строк, без сборки:**
  - CSS ~3,7 тыс. строк;
  - разметка всех экранов ~0,8 тыс.;
  - JavaScript ~13,5 тыс.: около 450 функций, около 220 общих переменных
    в одном замыкании;
  - переводы ru/ky/uz/zh ~2,6 тыс. строк внутри того же JS.
- **Бэкенд — Python, ~47 модулей в `core/`:**
  - `db.py` 4,8 тыс. строк, 258 функций, почти весь SQL;
  - `mufradat_api.py` — 75 адресов API приложения;
  - `bot_tg.py`, `handlers.py`, `scheduler.py` — логика ботов.
- **Данные:** SQLite на каждую половину (`quran_male.db`, `quran_female.db`);
  общая `sources/hadiths.db`, где вопреки имени лежат указатели заучивания и
  журнал действий; листы мусхафа `page*.json` генерируются и в git не хранятся.
- **Проверки:** 88 файлов тестов (все — сервер), CI не пускает красный код
  на прод, стенд со снимками экранов.

### Что сделано хорошо

- wiki с «почему», а не только «что»;
- тесты держат выкатку (`deploy` ждёт `check`);
- один код на две половины, базы раздельные;
- снимки стенда перед правками UI.

Слабость не в отдельных решениях, а в **структуре**, которая не поспевает
за ростом проекта и команды.

### Три проблемы — на примерах багов 05.11.2026

1. **Нет тестов интерфейса.** Надпись «Сначала пересдай, потом дальше»
   висела у всех шесть недель: дверь на дашборде вешала `openSubs` голым
   обработчиком, и объект клика попадал в флаг `fromWall`. Ни один из 88
   тестов не проверяет экран.
2. **Одно правило в нескольких копиях.** Правило перехода 40+40 записано
   трижды: `index.html`, `scripts/generate_hifz_audio.py`,
   `core/mushaf_words.py` (третью копию добавили 05.11 для склейки строк
   стр. 1–2). Пустые строки стр. 1–2 сломались потому, что приложение
   считало строки по экрану, а сервер — по данным. Закрытие долга
   продублировано в `_REDONE_EXISTS` и `is_retake_answered`.
3. **Один файл на всех.** 60 из 187 коммитов за 30 дней трогают
   `index.html`. Все правят один 18-тысячный файл; загрузка файла целиком
   через сайт GitHub может молча откатить чужую работу; ИИ читает файл
   кусками и легче пропускает связи между далёкими частями.

### Командная работа (Эрлан ↔ Абдусаттар)

- Хорошо: Эрлан работает через ветки и PR, пишет решения в
  `wiki/mushaf_yassirapp.md`.
- Риск: PR сливаются самим автором за 1–2 минуты, без ревью; тесты
  гоняются только после слияния в `master`.
- Риск: «Add files via upload» (PR #3) — при несвежей копии откатывает
  чужие правки без конфликта.
- Хвосты: слитые ветки не удалены, PR #1 открыт с июля.

Предложения: перед работой `git pull`, без загрузки через сайт; workflow
тестов на `pull_request`; автоудаление веток после слияния; на неделю
договариваться, кто какие экраны трогает.

## Часть 2. Уход от Telegram

### Это два разных проекта

1. **Уход от Telegram** — личность, вход, связь, группы. Почти целиком
   серверный и продуктовый: приложение знает о Telegram в ~10 местах
   (`initData`, `openTelegramLink`).
2. **Смена стека интерфейса** — TypeScript, сборщик, фреймворк.

Делать оба разом и за несколько недель — почти наверняка сорвать оба.

### Цифры с прода (05.11.2026)

| Показатель | Значение |
|---|---|
| Открыли приложение за 7 дней | 243 человека |
| Android / iPhone | 155 / 86 (64% / 35%) |
| iPhone на iOS 17+ | 85 из 86 (веб-пуш доступен) |
| Открывают внутри Telegram / в браузере | 82% / 18% |
| Активные студенты, не открывали приложение неделю | 19 из 233 |
| Сообщений бота в личку | ~550 в день |
| Сообщений в группах | ~980 в день |
| Мест в коде сервера, завязанных на Telegram | ~425 |
| Привязали вход по e-mail | 2 |

### Какие прежние решения это отменяет

- **«Telegram — это связь» (22.09):** бот может первым написать пропавшему.
  Эта возможность уходит — заменять сознательно.
- **Один бот, этап 2 (01.10, `wiki/one_bot.md`):** перевод групп на один
  бот теряет смысл, если группы уходят. Остановить, не доделывать.
- **Разбор 07.10 (`wiki/login_without_telegram.md`)** не отменяется — это
  основа: `identities(provider, subject, user_id)`, синтетический
  `app:<n>` в `users.phone`, развилка в отправщике.

### Три слоя связи с Telegram

1. **Исходящее — дёшево.** Вся отправка идёт через четыре нижних
   отправщика `core/tg.py` (там же перехват ленты). Замена — одна развилка:
   адресат без Telegram → «Входящие» в приложении + пуш. Дорог сам канал,
   а не 425 вызовов.
2. **Входящее и управление — основная работа:**

| Что | Сейчас | Без Telegram |
|---|---|---|
| Регистрация | join по ссылке; «брат/сестра» у @YassirAppBot | экран регистрации → подготовительная без чата |
| Членство, перевод, выпуск | ссылка, двойные join-события, кик | перевод в базе; кик = `active=0` (прецедент с 23.08) |
| Команды устаза/суперадмина | `/admin`, `/add`, `/approve_observer` | экран управления группой |
| Разбор устаза | уже в приложении | готово |
| Сдачи | с 16.09 только приложение | без изменений |
| Отметки, «у», узр | реакции и текст в группе | кнопки (частично есть) |
| Аудио | `file_id` + копия 7 дней | своё хранение; посчитать диск |

3. **Общение — решать по каждому чату.** Свой мессенджер не строим
   (модерация, медиа, взломы — см. 31.10).

| Чат | Предложение |
|---|---|
| Личка бота | заменить: «Входящие» + пуш; e-mail для пропавших |
| Учебная группа | заменить: объявления устаза в приложении; живой чат — вопрос |
| Тадаббур | заменить: лента «Общая» + утренний отчёт |
| Онлайн-урок | заменить: ссылка Meet/Zoom (где сейчас — уточнить) |
| staff | оставить в Telegram |
| Подготовительная | убрать чат; «виртуальная» группа, онбординг в «Знаниях» |

### Главная потеря — «вернуть ушедшего»

Пуш дойдёт, только если человек его разрешил; на iPhone — только если
приложение добавлено на экран «Домой». Закрываем: просить пуш при первой
сдаче, e-mail-дайджест молчащим 3+ дня, список «пропали» для устаза.
Показатель готовности — **доля активных с включённым пушем**.

### Вход

- **Рекомендация:** Google + Apple + код на e-mail. Бесплатно, без паролей,
  ложится на `web_sessions` и `identities`.
- **SMS-код:** платно за каждое SMS, доставка в КР/УЗ нестабильна —
  только если очень нужно.
- **App Store 4.8:** при входе через Google в приложении из App Store нужен
  равноценный вариант со скрытием почты — проще всего Sign in with Apple.
  Для PWA не действует.
- Нынешние студенты привязывают второй вход в настройках; история цела.

### Доставка приложения

| Вариант | За | Против |
|---|---|---|
| PWA (сайт) | бесплатно, мгновенно, пуш Android + iOS 16.4+ | на iPhone пуш только после «На экран Домой» |
| Магазины через Capacitor | нативный пуш, иконка в магазине, тот же код | платные аккаунты, ревью релизов, правило 4.2 («сайт в рамке») |
| Полностью нативное | максимум | переписать всё вместе с мусхафом; месяцы — не советую |

Предложение: сначала PWA + пуш, магазины через Capacitor — вторым шагом.

### Стек интерфейса

- **TypeScript — да.** Баг `openSubs` поймался бы при сборке. Шаг без
  сборки прямо сейчас: `// @ts-check` + JSDoc + `tsc --noEmit` в CI.
- **Vite — да, это смена деплоя:** сборка в CI, сервер раздаёт `dist`,
  хэши в именах файлов закрывают старый кэш PWA; меняются стенд, `sw.js`,
  проверка переводов; загрузка через сайт GitHub уходит.
- **React или Vue — по людям.** React: крупнейшая экосистема, лучше всего
  знаком ИИ, без трения с Capacitor. Vue: мягче вход, ближе к нашему HTML.
  Решает то, что знает и хочет вести Эрлан; при равенстве — React.
- **Мусхаф — отдельный чистый TS-модуль** при любом выборе (глифы V4,
  RTL, строки, подсветка, пометки). Туда же — **одна** копия правил 40+40
  (строки, половины, переход, склейка, шаг). Вариант: генератор пишет
  готовые поля в `page*.json`, и их читают приложение, сервер и генератор
  аудио.
- **Переход по экранам.** Новые экраны (вход, регистрация, «Входящие»,
  управление группой) — сразу на новом стеке; старые — когда их всё равно
  трогаем; мусхаф и заучивание — последними, с подробными снимками.
- **Без замеренной причины не делаем:** Postgres, микросервисы.

## Часть 3. Порядок этапов

Две связи работают параллельно; каждый этап включается и снимается флагом
(как `DM_VIA_APP`); переход к следующему — по замеренной доле, не по дате.

| Этап | Что | Готово, когда |
|---|---|---|
| 0. Основа | `identities`; Google/Apple/e-mail как второй вход; Vite + TS в CI; смоук-тесты экранов; «Входящие» + пуш, развилка в `core/tg.py` | ≥80% активных привязали второй вход, ≥70% с пушем |
| 1. Новички без Telegram | регистрация в приложении, виртуальная подготовительная, управление группой, ссылка на урок | неделя регистраций без «не могу войти» |
| 2. Личка уходит | бот не пишет в личку тем, у кого пуш; e-mail-дайджест | доля «пропавших за неделю» не выросла (сейчас 19 из 233) |
| 3. Группы | объявления и «Общая» в приложении; чаты закрываются по одному; боты половин выключаются; staff остаётся | откат флагом на любом этапе |

Параллельно и независимо, полезно уже сейчас:
1. смоук-тесты экранов на стенде (стенд и Playwright есть) — ~1 день;
2. `// @ts-check` + `tsc --noEmit` в CI;
3. workflow тестов на PR;
4. одна копия правил 40+40.
