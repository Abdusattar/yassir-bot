## 1. Как сейчас (замер 14.11.2026)

Страница мусхафа `page{N}.json` = вёрстка (строки, токены, шрифт V4, таджвид-разметка) +
арабский + **пословный перевод** (`translation` у каждого слова, дважды: в `lines` и в
`ayahs[].tokens`) + **смысл аята** (`ayahs[].meaning`). Каждый язык — полная копия страницы:

| Набор | Файлов | МБ | Где живёт |
|---|---|---|---|
| Мадина: `page{N}.json` (ru) + `_ky`, `_uz`, `_zh` | 4 × 604 | 27,7 + 30,1 + 29,9 + 29,2 | только сервер/локально (`.gitignore`); `_zh` кладётся tar+scp вручную |
| Дар аль-Маариф: `dm/page{N}.json` + `_ky/_uz/_zh` | 4 × 604 | 26,0 + 26,4 + 26,1 + 25,2 | **в git** (2416 файлов) |
| Итого | 4832 | ≈ 220 | |

Те же подписи — в базе `sources/hadiths.db`, таблица `mufradat_words` (тренажёр слов). Языковые
копии страниц делаются из ru-страницы скриптами (`export_mushaf_lang.py`, `patch_mushaf_ru.py`).

**Что из этого уже сломалось или стоит денег:**
- **Копии разъехались.** `page1_ky.json`/`page1_uz.json` (мадинская Фатиха) сделаны до правки
  разбивки строк Фатихи и до сих пор показывают старые строки: в строке 2 у ru первое слово
  «ٱلْحَمْدُ», у ky — «لِلَّهِ» и т.д. Кыргызский и узбекский студент видит другую вёрстку.
  Копия, которую надо помнить пересобрать, рано или поздно не пересобирают.
- Правка одной подписи = база + 604 мадинских файла на сервере (не в git — вне истории и
  отката) + 604 `dm/` файла в git. Каждый джуз перевода — десятки перезаписанных страниц
  в git (14.11: 44 файла на 123 подписи).
- Новый язык = ещё 1208 полных копий страниц (≈ 55 МБ), `_zh` — руками через tar+scp.
- Версии кэша — ручные числа в коде (`DM_DATA_VER = 2`, `MEANING_VER = '1'`): забыли поднять —
  телефон показывает старое (ловушка 29.08.2026).
- **Дыры в экспорте.** Аяты 8:6 (стр. 177) и 37:130 (стр. 451): в базе подписи есть, в страницах
  обеих раскладок — пусто, слова не тапаются. Сверка всего Корана (база + сегодняшние джузы 1–5
  против вшитого в страницы) — расхождений больше нет, только эти два аята. Новая схема их
  закрывает сама.

**Найдено попутно, к этому плану не относится, но срочно:** на проде `sw.js` с 02.11.2026
(коммит e761ce0) **не разбирается браузером** — в комментарии `meaning/*/*.json` стоит `*/`,
комментарий закрывается раньше, дальше синтаксическая ошибка (`node --check` на файле с
yassirilm.com/sw.js). Новый service worker не ставится: у кого стоял старый — живут со старым,
у новых пользователей офлайна нет. Исправление — одна строка комментария (в ветке
`wbw-split` сделано; для master — отдельной правкой).

Что сделано хорошо и берём за образец: смысловой перевод с 02.11 уже лежит отдельно —

## 2. Четыре вопроса (CLAUDE.md)

1. **Единственное место данных** — база, `mufradat_words` (на проде, общая для обоих ботов).
   Файлы для приложения — **результат сборки** из базы, руками не правятся. Страница —
   только вёрстка и арабский, без языка: одна на раскладку.
2. **Приложение или бот** — приложение: статичные файлы, nginx. С ботом связаны только тем,
   что база пока лежит в процессе бота; сборка файлов от бота не зависит.
3. **Тысячи студентов** — готовые файлы, на запрос сервер ничего не считает. Весь ru-Коран
   по сурам — 2,2 МБ, сжатым 643 КБ; самая большая сура (2) — 172 КБ / 45 КБ сжатая, малые —
   по 0,3 КБ. Файл с хэшем в адресе кэшируется навсегда, повторно не качается.
4. **Дорожная карта / долг** — долг уменьшается: уходят 3 копии × 2 раскладки (≈ 165 МБ),
   ручной tar+scp, ручные номера версий, перезапись `dm/` в git на каждой правке перевода.

## 3. Целевая схема

```
mufradat_words (база, ru/ky/uz/zh)          ← единственный источник
        │  scripts/build_wbw_chunks.py
        ▼
mushaf_data/wbw/<язык>/<сура>.json          {"s":2,"w":{"1:1":"Алиф Лам Мим", ...}}
mushaf_data/wbw/manifest.json               {"ru":{"1":"a1b2c3d4", ...}, "ky":{...}}  (хэш содержимого)

page{N}.json, dm/page{N}.json               вёрстка + арабский (перевод уходит на шаге 3)
meaning/<перевод>/<сура>.json               смысл аята (уже есть)
```

**Ключ слова — `сура:аят:позиция`**, не страница. Поэтому одна подпись обслуживает обе
раскладки, тренажёр и мусхаф: позиции у страниц и у `mufradat_words` общие (проверено
экспортом 27.08.2026, `export_mushaf_page.py`).

**Нарезка по сурам, а не по страницам и не по джузам.**
- По странице раскладки — снова привязка перевода к вёрстке: 604 × 2 раскладки × языки
  файлов, правка разбивки строк трогала бы переводы. Именно это мы и убираем.
- По джузу — тоже без вёрстки, но джуз режет суру, и чтение одной суры тянуло бы два файла.
- По суре — без вёрстки, тот же формат и загрузчик, что у `meaning/`, ключ `аят:позиция`
  естественный, правка одного слова меняет хэш одного файла. Страница затрагивает 1–3 суры
  (на последних страницах — 3–5 крошечных файлов); тяжёлый случай — сура 2, 45 КБ сжатая,
  качается один раз на все её 48 страниц.

**Что попадает в файл** — то же, что сейчас в `translation` страницы: подпись через
`_clean_translation`, «мусор» (`_is_junk`: «*», без букв) не кладётся вовсе. Для ky/uz/zh
кладётся только то, что есть на языке; **откат на ru — в приложении, по слову** (решение
пользователя 30.08.2026: перевод на другом языке полезнее пустоты) — так же, как сейчас.

**Приложение.** Один загрузчик листа вместо пяти копий `fetch(pageJsonUrl…)` (мусхаф,
заучивание, «Сегодня», тренажёр по листу, предзагрузка): берёт `page{N}.json` раскладки
(всегда ru-основу, без `_lang`) и файлы сур этой страницы на языке интерфейса (+ ru для
отката), вписывает `translation` в токены и отдаёт данные дальше — отрисовка, попап слова,
«Мои слова», пары слов (`mushafPairs`), подписи лёжа **не меняются**. Смена языка = другие
файлы сур, лист перерисовывается из памяти.

**Предзагрузка.** Уже есть окно 10 листов вперёд и 2 назад (11.10/12.11). Файлы сур тянутся
вместе с листом в той же очереди: на слабой сети следующий лист открывается с переводами.
Цена: первый лист новой суры ждёт один лишний запрос (манифест идёт параллельно с листом,
файл суры — после манифеста); дальше по суре — из памяти/кэша.

**Кэш: не чистить в конце сессии.** Пользователь предложил чистить; предлагаю иначе:
- При слабом интернете дешевле не качать заново: весь ru-перевод — 643 КБ, это два-три листа
  со шрифтами. Очистка «на выходе» заставляла бы качать при каждом открытии, а без сети
  (заучивание в дороге) переводы бы пропали.
- Свежесть держит **хэш в адресе** (`wbw/ru/2.json?h=a1b2c3d4` из `manifest.json`): исправили
  подпись — у суры новый хэш, телефон берёт новый файл при первом же открытии листа.
  Ручных номеров версий больше нет. Манифест маленький (≈ 5 КБ на язык), всегда со
  свежей сети (no-cache), без сети — последний виденный.
- Предел размера сам собой: service worker держит на (язык, сура) **одну** запись — при
  записи новой версии старые с той же сурой удаляются. Максимум — 114 файлов на язык
  (≈ 2,2 МБ ru). Язык, которым давно не пользуются, можно не держать (шаг 4, не сейчас).
- Аккаунт и личные данные в этих файлах не лежат, поэтому чистить их при выходе незачем.

## 4. Путь, по шагам, с откатом на каждом

**Что сделано в ветке `wbw-split`:** `scripts/build_wbw_chunks.py`, `tests/test_wbw_chunks.py`,
`app_src/js/034_wbw_words.js` (`fetchPageData` — один загрузчик для мусхафа, предзагрузки,
заучивания и «Сегодня»; тренажёр по листу берёт только вёрстку и не тронут), правки
`170_mushaf_pages.js`, `180_hifz.js`, `080_today.js`, `sw.js` (правила для `wbw/`, исправлен
комментарий), `.gitignore` (`mushaf_data/wbw/` собирается на сервере). Проверено: полный pytest
(841 passed); загрузчик прогнан в node на настоящих страницах и файлах из базы — ru совпадает
со вшитым (стр. 1, 50: 0 расхождений), стр. 177 получает переводы 8:6, zh берёт свои подписи с
откатом на ru, без манифеста — ровно старое поведение. Снимка экрана 390×844 ещё нет —
сделать перед выкаткой (на вид ничего не должно поменяться).

**Шаг 0. Сборка файлов из базы** (ветка `wbw-split`, сделано). `scripts/build_wbw_chunks.py
[язык …]` пишет `wbw/<язык>/<сура>.json` + `wbw/manifest.json`; одинаковый вход — одинаковые
байты (сортировка ключей), файл не перезаписывается без изменений. Тест сверяет: ru-файлы
дают ровно те подписи, что сейчас вшиты в `page*.json` обеих раскладок (0 расхождений);
нет ключей вне базы; «*» не попали. Откат — удалить папку `wbw/`, никто её ещё не читает.

**Шаг 1. Приложение читает переводы из `wbw/`** (ветка, сделано). Страницы не трогаем:
старые клиенты (старый `index.html` в кэше PWA офлайн) продолжают читать вшитые переводы и
`_lang`-копии — эти файлы на шаге 1–2 остаются на месте. Нет `wbw/` или манифеста (сеть,
сервер не собрал) — лист показывается с вшитым переводом, как сегодня. Откат — revert
коммита приложения.

**Шаг 2. Выкатка и правка конвейера** (после «да»). На сервере после `load_wbw_ru.py
--apply` (и `load_wbw_zh.py`, загрузки ky/uz) — `build_wbw_chunks.py`; лучше, чтобы загрузчики
звали его сами. nginx: `manifest.json` в `wbw/` — no-cache, `wbw/<язык>/*.json` — долгий кэш
(адрес с хэшем). `patch_mushaf_ru.py`/`export_mushaf_lang.py` для новых правок больше не
нужны. Откат — вернуть шаг 1, страницы со вшитым переводом всё ещё на месте.

**Шаг 3. Чистка страниц** (через ~2 недели после шага 2, когда старые клиенты обновились;
index у нас network-first, в Telegram no-cache — старые версии уходят за дни). Из
`page{N}.json` и `dm/page{N}.json` убрать `translation` и `ayahs[].meaning` (смысл — из
`meaning/`, панель «Смысл» перевести на него), удалить `_ky/_uz/_zh` копии (≈ 165 МБ, 1812
файлов в git), `dm/` перестаёт меняться от перевода. Откат — страницы из истории git
(`dm/`) / пересборкой `export_mushaf_page.py` (мадинские).

**Шаг 4 (не сейчас).** Выселить неиспользуемые языки из кэша; отдать `wbw/` с CDN.

## 5. Что с остальным

- **Тренажёр слов** — без изменений: читает `mufradat_words` на сервере. Теперь мусхаф и
  тренажёр гарантированно показывают одну подпись (один источник).
- **Две раскладки** — общие файлы переводов; `dm/` отличается только вёрсткой.
- **ky/uz/zh** — те же файлы по сурам; где слова на языке нет — ru-подпись (как сейчас).
  Новый язык = загрузить в базу + собрать (сотни КБ), без 1208 копий страниц.
- **Офлайн** — лист из кэша SW + файлы сур из кэша SW; манифест без сети — последний виденный.
- **Telegram WebView (без SW)** — nginx-кэш по хэшу в адресе, то же поведение.
- **«Мои слова»** — хранят копию подписи на момент добавления (как и сейчас), не меняется.
- **Тесты** — `tests/test_wbw_chunks.py`: сборка детерминирована, ru-файлы = вшитые подписи,
  манифест = хэши файлов; `test_app_build.py` — как обычно.

## 6. Чего НЕ делаем

- Не меняем формат вёрстки, шрифты, таджвид-разметку, отрисовку и попап слова.
- Не переносим сборку переводов в рантайм (API на каждый лист): готовые файлы дешевле.
- Не удаляем старые файлы до шага 3 и не трогаем прод до «да».
- Не трогаем смысловой перевод (`meaning/`) — он уже устроен так, как надо.
