# Ответ на разбор архитектуры и ухода от Telegram (08.11.2026)

Рецензия на `wiki/architecture_roadmap.md` от 05.11 — по просьбе автора
«проверить логику, найти, что упущено, оспорить порядок этапов и выбор
стека». Это мнение одной части команды, не решение: обсуждаем в группе,
принятое фиксируем в разделе «Решено» самого разбора.

## С чем согласны

Разбор принимаем за основу: деление на два проекта (уход от Telegram и смена
стека) правильное, делать их разом нельзя. Четыре вещи ниже оспариваем,
остальное поддерживаем.

- **Исходящее дёшево, входящее дорого.** Отправка идёт через четыре
  отправщика в `core/tg.py`, развилка «нет Telegram → Входящие + пуш» одна.
  Дорогая часть — регистрация, членство, команды устаза, аудио.
- **Этапы с флагом и откатом, переход по замерам, а не по дате.** Так и надо.
- **Вход: Google + Apple + код на почту, без SMS.** Поддерживаем, с двумя
  поправками в ответах ниже.
- **Сначала PWA, магазины через Capacitor вторым шагом.** Поддерживаем.
- **Мусхаф — отдельный модуль, правило 40+40 в одной копии.** Поддерживаем,
  это можно делать уже сейчас независимо от всего остального.
- **Без замеренной причины не трогаем Postgres и микросервисы.** Поддерживаем.

## Что оспариваем

### 1. Этап 3 (группы) недооценён

Группы дают не только объявления устаза, но и общину: видно чужие сдачи,
устаз рядом, пропасть неловко. В группах почти вдвое больше сообщений, чем в
личке (980 против 550 в день). «Лента плюс объявления» этого не заменяет.

Предложение: Telegram делаем необязательным для студента (этапы 0–2), а
группы не трогаем, пока этапы 0–2 не покажут цифры. Этап 3 в плане оставить
как «решим после этапа 2», без срока. Свой чат не строить, здесь автор прав.

### 2. Фреймворк переоценён, простые шаги недооценены

Все три бага из разбора лечатся без React и Vue:

| Баг из разбора | Что его ловит | Нужен фреймворк? |
|---|---|---|
| `openSubs` голым обработчиком | проверка типов (`@ts-check`, потом TypeScript) | нет |
| правило 40+40 в трёх копиях | одна копия: генератор пишет готовые поля в `page*.json` | нет |
| всё в одном файле на 18 тыс. строк | разрезать на файлы: CSS отдельно, словари в JSON, JS по экранам | нет |

Самое опасное состояние для маленькой команды с ИИ-помощниками — два стека
в одном приложении годами. План «новые экраны на новом, старые когда тронем,
мусхаф последним» ведёт именно туда: мусхаф и заучивание — большая часть
приложения, и они останутся на старом стеке надолго.

Предложение: сейчас TypeScript плюс Vite без фреймворка (модули по экранам,
один простой роутер вместо `style.display` по месту). Фреймворк обсуждаем,
когда в команде появится человек, который его знает. Веб-проекты тех, кто
сейчас пишет фронтенд, сделаны на чистом HTML, CSS и JS, так что критерий
«по людям» указывает не на React.

### 3. Разрешение на пуш — узел слабее, чем в документе

82% открывают приложение внутри Telegram, а там пуш запросить нельзя вообще.
Чтобы получить пуш на iPhone, студент должен пройти три шага подряд:

1. открыть yassirilm.com в Safari, а не в Telegram;
2. добавить на экран «Домой»;
3. разрешить уведомления.

Порог «70% активных с пушем» для этапа 0 при такой воронке может не наступить
никогда, и весь план встанет на первом шаге. Предложение: сначала замерить,
сколько людей уже сегодня заходят с экрана «Домой» (`navigator.standalone`),
и держать бота в Telegram основным способом позвать пропавшего, пока пуш не
догонит. Порог этапа 0 лучше привязать к одной группе-пилоту, а не ко всем
233 активным.

### 4. Дубли аккаунтов

Новичок, который на самом деле давно учится через Telegram, при регистрации
через Google создаст второй аккаунт с пустой историей. В разборе этого случая
нет. Нужна либо склейка аккаунтов, либо вопрос на регистрации: «Уже учишься у
нас? Тогда войди один раз из Telegram и привяжи почту».

## Ответы на вопросы к команде

Вопросы 2 и 3 — про практику устазов, там нужен ответ Умар устаза; ниже
только наше мнение.

| № | Вопрос | Наш ответ |
|---|---|---|
| 1 | Уходим полностью или Telegram необязателен? | Необязателен. Студент может учиться без Telegram, группы и staff остаются. Полный уход обсуждаем после этапа 2 по цифрам. |
| 2 | Где проходят онлайн-уроки? | Знают устазы. Для приложения важно одно: ссылка на урок должна лежать в карточке группы, а не в чате. |
| 3 | Нужен ли живой чат группы? | Да, но свой не строим: группы остаются в Telegram. Объявления устаза в приложении добавляем как дополнение, не замену. |
| 4 | Сайт (PWA) или магазины на первом шаге? | PWA. Android (64% студентов) получает пуш и без установки. Магазины через Capacitor потом, сначала Google Play (дешевле, без правила 4.2). |
| 5 | «Вход через телефон»: Google/Apple или SMS? | Google и Apple, плюс код на почту. SMS нет. Две поправки: Sign in with Apple даже для сайта требует платный аккаунт разработчика Apple; почту привязали всего двое, стоит понять почему, прежде чем строить на ней вход. |
| 6 | На чём сделаны веб-проекты фронтендеров? | Чистый HTML, CSS и JS без фреймворка и сборщика, PWA с service worker. То есть то же, что и Яссир сейчас. |
| 7 | Что должно случиться в ближайшие недели? | Список в следующем разделе. Ничего, что меняет привычки студентов, в эти недели не делаем. |

## Что предлагаем сделать в ближайшие недели

Всё ниже полезно при любом ответе на вопросы про Telegram и стек, не трогает
студентов и не мешает текущим правкам экранов (нижняя панель, дашборд).
Порядок — от дешёвого к дорогому.

- [ ] Тесты запускаются на pull request, а не только после слияния в master
  (одна строка в `deploy.yml`, деплой только на push).
- [ ] `// @ts-check` плюс `tsc --noEmit` в CI на текущем `index.html` (без
  сборки).
- [ ] Смоук-тесты экранов на стенде: каждый экран открывается без ошибок в
  консоли (Playwright уже есть в `scripts/`).
- [ ] Замер: сколько заходов с экрана «Домой», из браузера и из Telegram — по
  нему ставим реальный порог этапа 0.
- [ ] Одна копия правила 40+40: генератор пишет готовые поля в `page*.json`,
  приложение и сервер их только читают.
- [ ] Разрезать `index.html`: CSS в отдельный файл, словари ru/ky/uz/zh в JSON,
  JS по экранам. После этого толкучка в одном файле кончается, а Vite ложится
  сверху без переписывания.
- [ ] Второй вход (Google, код на почту) как привязка в настройках, пока без
  регистрации новичков. Apple после оплаты аккаунта разработчика.
- [ ] Решение по хранению аудио сдач без Telegram: посчитать сдач в день и
  средний размер файла, потом выбирать диск или облачное хранилище.

Решение о фреймворке и о судьбе групп в эти недели не принимаем: оба зависят
от замеров и людей, которых пока нет.

## Ответы на вопросы из `wiki/team_workflow.md`

1. **Где работаем с кодом.** До 08.11 — через сайт GitHub (загрузка файлов),
   потому что на машине не был настроен вход в GitHub. С 08.11 — git и
   `gh` из Claude Code: ветка, коммит, пул-реквест, слияние после «да»
   человека. Загрузки через сайт больше нет.
2. **Как запускаем Claude.** Claude Code (приложение), папка сессии —
   репозиторий, `CLAUDE.md` и wiki читаются сами.
3. **Стек веб-проектов.** Чистый HTML, CSS, JS, PWA с service worker, без
   фреймворка и сборщика.
4. **Что в правилах не сходится.**
   - Правило «сначала русский, ky/uz/zh потом» спорит с тестом
     `test_app_i18n_coverage`: он требует каждый русский ключ во всех языках
     и падает на ключах только на русском. Либо тест получает механизм
     исключений, либо правило звучит так: черновые переводы сразу, пометка
     «сверить носителю».
   - «ИИ-ревью PR» не определено: кто его делает и считается ли ревью
     собственным Claude автора. Предложение: UI-мелочь можно сливать по снимку
     и своему ревью, правки в `core/` и в логике сдач смотрит Claude другого
     участника.
   - Снимка 390×844 мало для низа экрана: обе ошибки нижней панели были видны
     только на живом iPhone, в PWA с экрана «Домой» и в Telegram поведение
     разное. Для правок нижней части экрана нужна проверка на телефоне в
     обоих режимах.
   - Листы `page*.json` не в git, снимки стенда без них пустые: в правило про
     стенд стоит добавить, откуда их взять.
   - Тесты на pull request, автоудаление веток и закрытие PR #1 поддерживаем
     целиком; ещё лучше потребовать зелёную проверку для слияния в master.
